# Бюро переселения привидений

Рабочее место оператора бюро: система подбирает каждому привидению место переселения, объясняет решение, показывает, кого расселить нельзя и почему, позволяет выбрать место вручную с предупреждениями и строит итоговый отчёт.

**Приложение:** https://ghost-bureau.vercel.app
**AI Worklog:** https://ghost-bureau.vercel.app/#worklog 
**Чеклист:** https://ghost-bureau.vercel.app/#checklist

## Проверка за минуту

1. Откройте приложение: загружен "обычный день бюро" (11 заявок, 6 мест, 9 расселены).
2. Нажмите на любую заявку. После этого, вы увидите расчёт баллов по факторам или причины, почему места нет.
3. "Выбрать место вручную" → место с нарушениями → окно подтверждения со списком.
4. Меню **"Сценарий"** сверху загружает каждое обязательное состояние из ТЗ одной кнопкой; вкладка **"Проверка"** то же с описанием, что ожидать.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
npm run build
npm run preview
```

Секретов и переменных окружения нет: данные хранятся в браузере (localStorage), их можно выгрузить и загрузить JSON файлом кнопками Экспорт и Импорт.

## Как подбирается место

1. **Обязательные условия** исключают место: нужен чердак, боится зеркал, нельзя рядом с людьми, нужна темнота (освещение ≤ 3), только в одиночестве; предел тревожности места; очень тревожным (8+) нельзя туда, где люди постоянно; просроченный дедлайн исключает все места.
2. **Баллы** (0–100) у оставшихся мест: база 50, температура до +25 (−3 за каждый градус разницы), шум −тревожность×шум/4, люди −тревожность×1,5 (иногда) или ×2,5 (постоянно), пожелания "любит сырость" и "любит тишину" ±10–15. Расчёт виден в карточке заявки по строкам.
3. **Порядок**: сначала ручные решения оператора, затем самые "трудные" привидения, у кого меньше подходящих мест, при равенстве — ближе дедлайн. Каждое получает лучшее место со свободной вместимостью. Тем, кому нужно одиночество, достаётся пустое место, а маленькие места для них предпочтительнее больших.
4. **Нет места** — причина сгруппирована по типу с названиями мест: "Слишком светло: Маяк (8/10), Библиотека (5/10)", "Все подходящие места заняты: …", "Дедлайн … уже прошёл".
5. **Ручной выбор** разрешён и с нарушениями — после подтверждения. Такое решение помечено "вручную", нарушения видны в карточке, на загрузке мест и в отчёте; если есть место заметно лучше, система подскажет.

## Обязательные состояния из ТЗ

| Состояние | Где увидеть                                                                                                            |
|---|------------------------------------------------------------------------------------------------------------------------|
| Пустой список заявок | Сценарий "Пустой список заявок"                                                                                        |
| Заявка без подходящего места | "Графиня Без-Отражения" в любом сценарии, отдельно "Заявка без подходящего места"                                      |
| Место переполнено | Сценарий "Место переполнено": часовня 3/1                                                                              |
| Ручной выбор конфликтует с условиями | Сценарий "Ручной выбор с конфликтом" или выбор вручную любого места с нарушениями                                      |
| Понятное сообщение об ошибке | Вкладка "Проверка" → "Испортить сохранение"; импорт неверного файла; сбой в интерфейсе общее сообщение с перезагрузкой |

```

src/content/      текст AI Worklog

tests/e2e/        сценарии в браузере
```
